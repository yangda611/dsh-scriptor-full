# 灵感与立项（Novel Inspiration）

本技能覆盖「零散脑洞 → 候选探索 → 可立项构想 → 建书」。先判断作者要记录、探索还是立项；一次重点解决一两个方向问题。未经作者明确批准，严禁进入建书。

## 标准流程

作者要求探索时，给两类可比较方向：熟悉题材中由人物处境和选择长出的新发展，以及特殊设定及其后果推演。每类用一小段故事发展讲清处境、动机、选择、后果和期待，再给少量自然长出的开放分岔。差异不能只有换人名、地点或能力名称；题材惯例只是参考，不自动成为硬限制。不用临时设定、人物失智或固定反转配额制造新意。

短段发展用于探索，不是待入稿正文。分岔可以全部推翻，不预设终点，也不自动成为正式路线、事实或兑现义务。可用问答、具体发展试探、人物选择推演或参考作品分析，不连续出选择题代替材料。作者表达偏好后保留他喜欢的部分、改变不满意的机制；已有信息足够就先提建议，一次只追问最影响方向的一件事。已有明确路线时沿该路线探索，不强迫重新二选一。方向清楚后再收敛七要素；明确只想记录时不启动探索。

### 提问方式：先给选择，再兜底手动输入

从第一次对话到建书完成，一共三步，每步开头先告诉作者现在是第几步、这一步要定什么、后面还剩几步。**每个要作者定夺的点，先给 3–4 个具体选项**（按已定的市场与题材库出真实内容，不是空泛的 A/B/C），让作者说编号或直接说选项；**最后加一个“自己有想法，手动输入”的选项**。作者也可以一次回答多个点，或直接改你给的草案。**绝不在没有给选项的情况下问开放式问题**，不要让作者每次都必须手动打字。每个选项旁标明哪一个是推荐（★推荐）或默认；作者不选就按默认来。作者选完后简短确认一句（“好，定下来了：……”），直接进下一步，不重复问已经定好的事。

1. **随手记**：仅要求记录时，保留作者原意，不评判、不主动展开。用通用写工具落到灵感池 `<工作范围>/书房/灵感池/`，一条脑洞一个 `.md`，frontmatter 三项——`状态: 候选`、`身份:` 与文件名同值、`来源快照:` 落 ISO 时间戳。探索中将值得保留的候选与作者原话区分记录。
2. **收敛七要素**（要素名与 `novel_create_book` 的 `concept` 参数字段逐字对应，呈报与调用照抄）：
   - **核心创意**——一句话卖点；
   - **题材与目标读者**——大类+细分与对标气质；
   - **主角核心欲望**——最想要什么，动机能否支撑长篇；
   - **主要冲突**——谁在阻碍，能否逐级升级；
   - **核心看点**——追更的爽点/悬念/期待感；
   - **差异化方向**——同类里独特的记忆点；
   - **明确不要什么**（创作禁区）——明确不写的桥段、人设、走向。
   - **做法：先给草案，再让作者改**——根据作者已说的想法和题材库，先把七要素填成一份草案给作者过目；作者只改想改的部分，不用逐个回答。草案里定不下来的要素先写「留白」，不要为了填满而编。草案里每个未定要素附 3–4 个具体选项 + “自己有想法，手动输入”；作者可以一次定多个要素。`核心创意` 与 `题材与目标读者` 两项必须非留白，其余五项可留白，不要求全部定死才立项。
3. **呈报确认**：七要素整理为构想草案，用通用写工具落 `<工作范围>/书房/构想/<书名或代称>.md`，再呈作者；获明确同意后调 `novel_create_book`，七个要素字段一个不缺地给全，`concept.状态` 必须为「已确认」。

   **建书前先定市场、输出形态与目标总字数**（调 `novel_create_book` 之前，**三项放在同一条消息里一次问完**，各给选项，大白话，别用术语；**三项是硬关卡**：缺任何一项工具都会直接拒绝，不许用默认值悄悄建书——默认值只在作者明确说“就按默认来”时才用）：
   - 市场——“这个项目面向海外还是中文市场？”：1. 中文（★推荐，默认）——给国内观众，用中文题材库（赘婿、战神、霸总等）；2. 海外——给海外观众，用海外题材库（狼人、亿万富翁、黑手党等）；3. 自己有想法，手动输入。作者不选默认 `中文`。
   - 输出形态——“要出短剧、电影剧本还是小说？”：1. 小说（★推荐，默认）——长篇小说，走原来的写章流程；2. 短剧——一集一集的短剧，走分集大纲 → 单集剧本 → 审读；3. 电影剧本——一部电影的剧本，走故事稿 → 分场大纲 → 剧本草稿 → 审读；4. 自己有想法，手动输入。作者不选默认 `小说`。
   - 目标总字数——“这本书目标写多少字？”：1. 短篇·5万字；2. 中篇·30万字；3. 长篇·100万字（★推荐，默认）；4. 超长篇·200万字；5. 自己有想法，手动输入具体数字。作者不选默认 `100万字`。这个数写进作品契约 frontmatter（`目标总字数`），用来规划篇幅；每章的字数另在定调时商定（`章节篇幅`），不是同一个数。
   - **书房面板也能点**：作者可以在书房面板点“新建书”，三项点选卡片点三下就保存好；选好后聊天里不用再问，直接调 `novel_create_book` 即可（工具会读取面板保存的选择）。作者在面板选好后，不要在聊天里重复问。
   - 三项一旦写入作品契约 frontmatter（`市场` / `输出形态` / `目标总字数`），建书后不再静默改写；作者之后想改，走契约修订流程。旧书没有这些字段时按默认值（中文 / 小说）处理，目标总字数缺失时不自动补写。
4. **跃迁**：建书由工具完成——书仓脚手架、构想快照冻结、书id 写入契约、`vol:` 首次提交（草稿区不入库），设计面跃迁为「作品定调」。**建书不自动切书**：拿 `novel_create_book` 返回的 `bookId` 调 `novel_select_book` 落定当前书，再向作者说明去向——**默认走快速开写**（《定调设计》路径 A：一次起草、作者过目确认）；只有作者明确说要逐部细聊、深度定制时，才走深度定制（《定调设计》路径 B：逐部细聊）。

## 工具

| 工具 | 何时用 | 不要 |
|---|---|---|
| 通用写工具（灵感池） | 每个脑洞当场落 `书房/灵感池/` | 把灵感池当真源;写在书仓里 |
| `novel_create_book` | 七要素已确认、市场/输出形态/目标总字数三项都有答案后一次调用（缺任何一项工具直接拒绝） | 构想不完整或未确认时调用;三项没问完就调用;重复建同名书 |
| `novel_select_book` | 建书返回 `bookId` 后落定当前书 | 未经作者明确指定就切到别的书 |
| `novel_record_memory` | 作者明确要记，或已确认且长期有用的结论；先查重并明确范围 | 临时探索不入记；七要素本体留在构想，不再抄一份 |

## 灵感元数据

新灵感条目可在原三字段之外另加 `schemaVersion: 1`、`类型: 随手记|对谈候选`、`标签: [标签]`；旧条目和自由正文无需迁移，未知字段保留，`来源快照` 始终是 ISO 记录时间。

## 从参考作品产生新点子

按当前问题选择性调用 `novel_reference_query({action: 'search', query, tags?})`，分别看作者点子与有效参考机制；不强制每次都搜索。想从自备小说拆解时加载 `novel-analyze`；没有原文或可用分析时，只能推荐正规获取链接或讨论公开作品资料，不能声称已经拆过。

引用机制说明一般问题及成立条件，再由本书人物、处境和规则重新推演具体发展。原作特有事件链、人物组合和结局不能直接变成本书路线；原作事实不能写成本书账本事实。多书相似之处只称多书观察，不当原创性、版权或市场效果证明。

探索实际产生新点子后，用 `novel_reference_report` 的 `save-idea` 自动保存候选，提供固定的 `参考书/原文版本/机制/机制版本` 引用、正文、标签及本次 `operationId`，同次失败重试沿用身份，不为同源不同点子复用身份。机制生成本身不入池；作者明确收藏机制时存简短笔记与引用，机制正文仍在参考库维护。入池不等于本书采纳，正式采用仍走既有确认流程。依据失效只提示核对，不删除或改写作者点子。

## 重入（作者推翻构想）

- 本书建成后其构想不回改：方向变化走契约修订（《定调设计》），构想快照冻结；**开另一本新书仍走本技能**；
- 未建书、推翻部分要素：只重聊被推翻的项，已收敛项从 `书房/构想/` 的草案里复用，区分字段缺失与合法留白，不把其余五项留白当成不能立项；
- 灵感池旧点子可随时翻出重组。

## 工件契约

| 工件 | 路径 | 属性 |
|---|---|---|
| 灵感池条目 | `<工作范围>/书房/灵感池/<身份>.md` | 书房资产非真源;frontmatter `状态: 候选`／`身份`／`来源快照`;不入书仓 git |
| 构想草案 | `<工作范围>/书房/构想/<书名或代称>.md` | 书房资产非真源;模型手写;建书前七要素的唯一载体,换会话靠它接上 |
| 作者层记忆条目 | `<工作范围>/书房/作者记忆/<名称>.md` | 只记明确跨书的偏好；`scope: author`，不传 bookId；名称、描述、类、来源、正文必填，标签可选；索引由工具同步 |

记忆遵守《工作台总控》的保守规则。建书前的临时方案留在构想草案；作者要求保存的脑洞放灵感池。已有书的取舍理由属于本书，传 `scope: book` 和 `bookId`。同一事项先读旧条目再更新，不不断新建记录。没有长期价值就不写记忆。
| 构想快照 | `<书仓>/构想/构想快照.md` | 工具生成,建书后冻结只读 |
| 首提交 | `vol:` 前缀 | `novel_create_book` 自动完成 |
