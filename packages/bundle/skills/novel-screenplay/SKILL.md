# 电影剧本改编（Novel Screenplay）

只给一种项目用：建书时选了「输出形态：电影剧本」的项目。小说项目走原来的长篇流程，短剧项目走短剧管线，别混用。

先读契约再动手：`作品契约/契约.md` 的 frontmatter 里有两项——

- **市场**（`市场`）：`海外` 用海外题材库（狼人、亿万富翁、黑手党等），`中文` 用中文题材库（赘婿、战神、霸总等）。选了海外就不要往里塞赘婿、婆媳、纯修仙这些外国观众无感或流失快的题材；选了中文就按国内备案与内容禁区走。
- **输出形态**（`输出形态`）：必须是 `电影剧本` 才进本技能。不是就停下，告诉作者走错了管线。
- 旧书没有这两个字段时，按默认值处理（`中文` / `小说`），不要自动补写、不要擅自改写。

## 四步流程（一步一步来，不要跳步）

### 第 1 步：故事稿（小说浓缩版）

先把故事用散文写透，再改编。故事稿不必是完整长篇小说，只需浓缩故事稿——故事逻辑、人物动机、世界规则在散文里过一遍，剧本继承这个深度。

- 写什么：六节——`故事一句话`、`人物小传`、`世界规则`、`情节主线`、`关键转折`、`结尾`。人物小传里必须写清每个人的动机（想要什么、为什么非要不可）；没有特殊规则也要写「无特殊规则，现实世界」。
- 工具：`novel_screenplay_validate_story` 校验结构（缺节、空节、无人物、无转折会报错；动机没写清只报警告）。
- 中间稿位置：`草稿区/剧本/故事稿.md`（草稿区，可丢弃可重建，大胆迭代）。
- 这一步不过，绝不进分场。

### 第 2 步：分场大纲（三幕结构）

按三幕结构分场，场号两位（场01、场02……全片从 01 连续编号），每场写清四项：场景、人物、冲突、转折。

- 工具：`novel_screenplay_build_outline` 从故事稿生成骨架——第一幕 1 场、第二幕每条关键转折 1 场（转折原句直接落进该场）、第三幕 1 场；场景和冲突留【待写】，由你逐场写完。骨架不是成品大纲。
- 校验：`parseSceneOutline` 的规则——三幕都要有场、场号连续、四项齐全，缺一项都过不了。
- 中间稿位置：`草稿区/剧本/分场大纲.md`。

### 第 3 步：剧本草稿（编剧层分场景格式）

- 工具：`novel_screenplay_build_draft` 从分场大纲生成骨架（每场一个场景标题，动作与台词各留一处【待写】），再由你逐场写成正文。
- 格式（专业影视级，六大元素）：
  - **场景标题**：`场01 INT. 会议室 - 日`——场号两位 + `INT./EXT. + 地点 + 时间`，全大写；时间多用 日/夜/黄昏/清晨/傍晚/深夜，除非时钟本身是剧情点，不写具体钟点。
  - **动作行**：现在时，只写看得见/听得见的，不写人物内心想法；段落宜短。
  - **角色名**：说话人姓名全大写，居中于对白上方；首次出场姓名全大写（海外项目里的 Selene、Jackson 写成 SELENE、JACKSON）。
  - **台词**：无引号、口语化；被打断用 `--`，拖长/欲言又止用省略号 `...`。
  - **括号提示**：小写、简短、少用；只在台词本身无法传达语气/对象时才用。
  - **转场**：少用，只在转场本身有意义时用；以 `FADE IN:` 开场、`FADE OUT.` 收尾。
- **停顿写法（定死了，三选一，不混用）：只用 `(pause)`**。不要用 `(beat)` 表示停顿——ScreenCraft 明确反对，认为 beat 在表演术语里含义不止“停顿”。省略号 `...` 表示拖长/欲言又止，不是干净的停顿。校验会把 `(beat)` 判为高级别错误。
- **音效与音乐**：音效写进动作行（关键音效词大写/明确提示，如“此时传来剧烈的爆炸声”）；`SFX:` / `MUSIC:` 独占一行是 BBC 广播剧格式，不是电影剧本格式，禁用。音乐提示不进编剧层，那是阶段 4 导演层分镜头表的事。
- **镜头提示**：编剧层克制着写，除非该镜头对理解场景不可或缺，否则不写（属于导演职权）；写了只报低级别警告。
- 中间稿位置：`草稿区/剧本/剧本草稿.md`。

### 第 4 步：审读（四模块，经共享审读注册表）

- 先跑技能脚本（只算不写）：`node <resourceBase>/scripts/剧本格式检查.mjs --草稿 <剧本草稿路径> --大纲 <分场大纲路径> [--片长 长片|短片]`，拿到回写载荷。
- 再调 `novel_screenplay_review` 跑三个确定性模块：**剧本对白审读**（角色名、台词、括号提示、停顿）、**剧本节奏审读**（三幕、转折、开场钩子、场次下限、长片页数参考）、**剧本场次完整性审读**（大纲与草稿场场对应、场号连续、无【待写】占位）。三模块已注册进共享审读注册表（适用范围 剧本，与章节审读同一套完成判定逻辑；章节完成判定不受影响）。
- 工具返回发现项 + **审核编号**（固定 `审-剧本`）+ **审读指纹**：确定性发现项与语义发现项一并经 `novel_record_review_findings`（适用范围 剧本，传同一份剧本草稿/分场大纲文本与审读指纹）回写进剧本审读记录（`草稿区/审核/审-剧本.json`）。指纹对不上会被拒绝（已过期），不要换成后来取得的值。
- 任一高级别发现项即阻断，不得进定稿；语义深挖（对白像不像这个人、转折可不可信）按底本派发：默认用 `底本/全量审读.md` 一次派发跑完三维，定向加深才派单维底本；语义模块名 **剧本语义审读**，发现项同样经上述回写通道落盘。四个范围模块（三个确定性 + 一个语义）全部回写完毕才算审核完成；长剧本尤其要走完这一步，否则上下文漂移、人物不一致没人兜底。
- 审读通过后，定稿落到 `剧本/电影/剧本.md`（阶段 0.5 已有的 `paths.电影剧本()`，不要另造路径）。

### 第 5 步：导出（默认《痴迷》式分镜剧本）

- 导出默认出《痴迷》式分镜剧本：`computeScreenplayExport` / CLI 不传 `--格式` 时，产出总纲七节（第六节为三幕结构与时间锚点）+ 每场按动作行/台词段出的 △分镜块（时间｜景别｜角度｜运镜 五字段齐全，景别/角度/运镜填 `—` 待导演填，时间码按页数×55 秒分配；对白括号提示作语速/音量/语调标注，不编造）。这是给 AI 影视制作的生产剧本，不是传统编剧层。
- Fountain 与 master-scene（`FADE IN:` / `INT. 场景标题`）是次要导出：`--格式 fountain` / `master-scene` / `both`（三份文件）才出；分镜头表（导演层）仍可作派生文件另出。

## 电影节奏模板（钩子与爽点分布）

长片 90–110 页，一页约一分钟是经验法则（实测约 55 秒/页，整本估算可用、单页不可）。三幕：第一幕约 25%（建置：立主角、立世界、立核心冲突，第一场就进冲突，激励事件把主角推出日常）；第二幕约 50%（对抗：冲突升级，中点大反转，每幕至少一个转折）；第三幕约 25%（结局：高潮对决，兑现全片承诺）。全片数个转折点——不是短剧的每集三钩，别把短剧密度套到电影上。对白可长、可潜台词。

## 工具清单

| 工具 | 用途 |
|---|---|
| `novel_screenplay_check_contract` | 门禁：输出形态是不是电影剧本、题材档属不属于该市场 |
| `novel_screenplay_validate_story` | 校验故事稿结构 |
| `novel_screenplay_build_outline` | 故事稿 → 分场大纲骨架 |
| `novel_screenplay_build_draft` | 分场大纲 → 剧本草稿骨架 |
| `novel_screenplay_review` | 三模块审读一次跑完 |
| `novel_screenplay_render` | 渲染标准格式文本 + 页数粗估 |

## Off-limits

- 只在输出形态为电影剧本的项目里用本技能；小说流程一个字都不动。
- 骨架（【待写】占位）不是成品：骨架过不了审读是正常的，不要为了让审读变绿而删发现项。
- 停顿只用 `(pause)`，不要混用 `(beat)` 或拿省略号当停顿。
- 音效进动作行，音乐提示不进编剧层；镜头提示克制。
- 定稿只认 `剧本/电影/剧本.md`；中间稿在草稿区，作者批准前不进定稿。
- 格式与节奏规则以调研为准（`docs/research/film-drama-research.md` 第 1 节、第 2.5 节），不要凭空编；调研没给的数（如三幕页占比）是工具内约定，不要说成是调研结论。
