# 最小导出（Novel Export）

把**已定稿**正文按章序导出成可连续通读的 Markdown 副本。只读真源，不改书仓；草稿、候选事实、运行审计一律不导出。当前只做本地 Markdown，不做平台格式、PDF/EPUB 或在线发布。

## 标准流程

1. **问清范围与目标**：与作者确认导出范围（默认全书；可按 `--卷`、`--起章`/`--止章` 连续章号圈选）和目标目录（书仓外、作者选定）。
2. **跑脚本（只算不写）**：`node <resourceBase>/scripts/最小导出.mjs --book <bookRoot> [--卷 N] [--起章 N] [--止章 N] [--目标 目录]`。stdout 给出范围、章数、两份文件全文与目标检查结果（冲突、拒绝原因）；失败按《工作台总控》「脚本失败分流」表处理。空选择、目标落在定稿目录内都会明确报错，不会静默产空文件。
3. **呈报计划**：向作者说明章数、合计字数、文件名与目标目录；目标里已有任一同名文件时脚本拒绝新建，逐个说明冲突并另选新目录。**不支持原位覆盖**；作者要求更新旧导出时，在新目录生成一批完整副本，保留旧批。中断留下的文件也不删除、不覆盖。
4. **写盘与验收**：作者确认后用原生文件工具在新目标创建——先写 `*-定稿合集.md`，再写来源清单。发生文件已存在、权限失败或取消时停止并报告未完成，保留旧批与本次残留；重新导出另选新目录。写盘后用同一范围运行 `node <resourceBase>/scripts/最小导出.mjs --book <bookRoot> --目标 <目录> [同一范围参数] --校验 true`，它会读取实际合集和清单，逐份比对字节哈希；只有 `ok:true` 且 `校验.ok:true` 才报告完成。清单存在或两次源稿计算哈希相同都不能代替验收。校验失败保留文件，说明缺失/内容不一致，不能宣称完成。

5. **交付成品**：仅在上一步实际文件校验通过后，调用 DSH 的 `present`，以 `files: [{ path: 合集绝对路径, description: '已校验的定稿合集' }, { path: 清单绝对路径, description: '来源与版本校验清单' }]` 声明两份成品。使用本次校验的真实路径，不把计划路径或残留文件当成品。若 `present` 不可用或失败，明确说明“文件已生成并校验，交付卡未创建”，提供文件路径；不要重新写盘或重复导出。交付卡打开的是当前源文件，不保存内容快照；文件移动、删除或修改后，卡片不保证仍是本次校验的版本。

## 剧本导出

电影剧本与短剧单集走同一只读纪律，脚本不同：`node <resourceBase>/scripts/剧本导出.mjs --book <bookRoot> --形态 电影剧本|短剧 [--集 N] [--格式 fountain|markdown|both] [--分镜头 表格路径] [--总纲 总纲JSON路径] [--目标 目录] [--校验 true]`。只算不写，stdout 给出两份文件全文与目标检查结果；传了 `--总纲` 再多一份总纲文件与人名检查结果。

1. **读真源**：电影读 `剧本/电影/剧本.md`（全文一份），短剧读 `剧本/短剧/集001.md`（每集一份，`--集` 必传，1–100）。草稿区里的剧本草稿不是真源，不导出。
2. **两层分开**：Fountain（`.fountain`）只出编剧层——场景标题、动作、角色、台词、括号提示（停顿只用 `(pause)`）；Markdown（`.md`）在编剧层之外另附导演层 `分镜头表`（镜号/场/景别/角度/运镜/时间/时长（秒）/画面内容/台词/对白标注/音响/字幕/音乐）。音效写进动作行，音乐提示只进分镜头表音乐栏；`SFX:`/`MUSIC:` 独占行是广播剧格式，出现即报错，不进导出文件。
3. **分镜头表**：导演已填的表用 `--分镜头` 传 Markdown 表格（表头须与导出文件里的表头逐字一致；旧版 10 列摄法表头仍可解析，摄法映射为角度）；不传则按场生成待填模板行（景别/角度/运镜/音响/字幕/音乐填 `—`，时间与时长空着），由导演补，工具不编造景别与运镜。模板行的待填项进 `警告`，不阻断。
4. **写盘与验收**：与最小导出同一纪律——目标目录不得落在 `定稿/` 或 `剧本/` 内（会污染真源），已有任一同名文件时拒绝新建、不覆盖；作者确认后用原生文件工具写盘，写盘后用同一参数加 `--目标 <目录> --校验 true` 跑一遍，只有 `ok:true` 且 `校验.ok:true` 才报告完成。文件名：电影 `<书名>-电影剧本.fountain` / `<书名>-电影剧本.md`，短剧 `<书名>-短剧集001.fountain` / `<书名>-短剧集001.md`。
5. **阻断**：定稿缺失、剧本解析失败、电影剧本有高级别格式发现项（`(beat)`、空场等）、分镜头表镜号不连续或场号越界时，脚本直接报未完成，不产文件。
6. **总纲与人名检查**：`--总纲` 传总纲 JSON（StoryBibleInput 七节，见 `docs/book-format.md`「总纲」）时，导出多出 `<书名>-总纲.md`，并以总纲第五节为人名注册表做导出前一致性检查——全剧人名必须在册且只用标准名，未登记/误标直接阻断，不静默输出。说明/场景/动作文字一律中文，对白按目标市场语言（总纲 `对白语言` 字段写明）。

## 纪律

- 合集正文与定稿逐字节一致：不润色、不摘编、不重排章序；卷/章标题由脚本生成，正文一字不改。
- 导出是只读副本：来源清单注明每章相对路径、版本与内容 SHA-256，便于回查；导出本身不改真源、不改 Git。
- 目标目录通常在书仓围栏外，原生写盘可能触发 DSH 提权确认——如实说明要写的两个文件名与位置，不批量扩大授权。
- 平台格式适配、发布不在本技能范围；作者提这些需求时如实记录，不现场拼凑。
