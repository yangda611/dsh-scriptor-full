# 书仓格式与修改边界

此文概述贡献代码时必须保留的公共契约。解析与写入实现位于 `packages/core/src`，测试中的合成夹具是可执行示例。

## 文件真源

书仓通常包含 `构想`、`作品契约`、`大纲`、`世界书`、`定稿`、`账本`、`本书记忆` 和 `草稿区`。工作范围内的 `书房` 保存跨书素材。书 id 来自作品契约，不能凭目录展示名替代。

卷目录形如 `卷01`，章号全书连续，文件中的章号使用既有四位编号规则。不能把“本卷最大章号”当作本卷章数，也不能把窗口耗尽当作整卷完成。

结构化 Markdown 的 frontmatter、版本、模块标题、引用路径和哈希由对应解析器处理。草稿/候选不是已确认设计，定稿不是聊天里的一句“完成”。恢复进度从当前文件推导，不额外维护一套会话状态账。

## 写入约束

### 章节篇幅约定

在作品契约的“阅读体验与情绪承诺”分部内，使用可选三级子节记录本书篇幅。下面是目标两千汉字的宽松示例，具体数值由作者确定：

```markdown
### 章节篇幅
- 目标汉字数: 2000
- 下限汉字数: 1600
- 上限汉字数: 2400
```

子节只含这三项正整数，满足下限 ≤ 目标 ≤ 上限；其他说明放在相邻子节。沿用 `novel_update_contract` 更新该分部，保留其中已有内容；所在分部确认后生效。缺子节的旧书保持兼容，不自动套默认范围。

细纲和起草继承约定，按本章任务分配预计篇幅。审读脚本按正文汉字数核对，包含章标题、排除 frontmatter 与候选事实；范围外的情况进入原“文本规范检查”发现项，沿用修改或作者保留等处置。没有新增审核步骤，也不自动裁稿。契约修改后旧审读证据失效，需按原流程重跑。

### 通用写入规则

- 所有输入路径均是受校验的仓内相对路径；拒绝盘符、路径逃逸、保留名和不受信任链接。
- 候选与普通文档修改复用原生观察和精确写入授权；并发修改使旧观察失效。
- 多文件定稿/沉淀保留事务边界，失败可恢复，不能拆成若干无保护覆盖。
- 作者批准绑定本次操作。取消、拒绝或迟到答复不能授权写入。
- 定稿、构想快照和其他冻结工件不通过普通编辑直接覆盖；影响已定稿内容的变更走已有补偿流程。
- 成功后可核对文件、账本及 Git 提交；提交失败不得重复升版或重写相同正文。

## 检索与派生数据

`草稿区/批次/<批次名>/批次.json` 是连写批次的保留声明，当前没有生产器、消费者或运行时校验；路径识别不表示已经实现连写调度。

索引、缓存和材料包具有来源与新鲜度要求，不能代替正文、确认规划或账本。模型、维度、指令或原文变化后应按各自契约失效；模型服务失败时显式降级，不伪造增强效果。

## 兼容性

修改字段、路径、确认状态或格式版本时，附旧数据夹具、迁移/回退说明和验证。预览期也不能把不兼容数据变化藏在普通 patch 中。v6/v7 旧书不属于已验证的自动迁移输入。

## 8.4.0旧格式退出

正常读取不再恢复旧线索/时间线正文前缀、不解析有内容的旧记忆分类文件、不接受旧特殊字符字面索引目标。检查会说明旧形态，维护预览仍可识别受支持的源并生成完整迁移差异。合法空记忆分类、当前字段及明确编码链接继续有效。升级要经作者批准；浏览与插件安装均不自动改写书仓。

## 影视剧扩展（muse-dev，v8.4.1 之后新增）

### 市场与输出形态（契约 frontmatter 字段）

创建项目时选定两项，写入作品契约 frontmatter，之后不再静默改写：

- `市场`：`海外` | `中文`。决定加载哪套题材库（海外题材库 / 中文题材库）。默认值：`中文`。
- `输出形态`：`短剧` | `电影剧本` | `小说`。决定走哪条流水线。默认值：`小说`（与旧行为一致：未指定形态的项目按小说处理）。

两字段均为单行文本，已登记进 `packages/core/src/repo/document-fields.ts`（`DOCUMENT_FIELDS`），值用 `isDocumentFieldValue` 校验；非法值拒绝写入。输出语言恒为中文（团队自己拿去拍），市场只影响题材库，不影响输出语言。

### 剧本定稿目录

新建顶级目录 `剧本/`，与 `定稿/` 平行，只放已定稿的剧本（草稿/候选仍在 `草稿区`）：

- `剧本/电影/剧本.md`：一部电影的已定稿剧本（全文一份）。
- `剧本/短剧/集001.md`、`集002.md`、……：一部短剧每集的已定稿剧本（每集一份，集号三位）。

不要把剧本定稿放进 `定稿/`（会污染小说导出）；不要把小说定稿放进 `剧本/`。

### 剧本导出（阶段 4；对齐轮次按《痴迷》参考案例对齐）

导出读 `剧本/` 定稿，不写书仓；Fountain（`.fountain`，编剧层纯文本）与 Markdown（`.md`，编剧层 + 导演层）双输出，确定性生成（无时间戳）：

- 文件名：电影 `<书名>-电影剧本.fountain` / `<书名>-电影剧本.md`；短剧 `<书名>-短剧集001.fountain` / `<书名>-短剧集001.md`（集号三位）；传了总纲再加 `<书名>-总纲.md`。
- 两层分开：编剧层（场景标题/动作/角色/台词/括号提示，停顿只用 `(pause)`）与导演层（分镜头表：镜号/场/景别/角度/运镜/时间/时长（秒）/画面内容/台词/对白标注/音响/字幕/音乐），不混写。音效写进动作行，音乐提示只进分镜头表音乐栏；`SFX:`/`MUSIC:` 独占行是 BBC 广播剧格式，不进电影剧本。旧版 10 列分镜头表（摄法栏）仍可解析，摄法映射为角度。
- 分镜头表：导演填的 Markdown 表格（表头固定列序，见 `packages/core/src/export/screenplay-format.ts` 的 `SHOT_TABLE_HEADERS`）；不提供时导出按场生成待填模板行（景别/角度/运镜/音响/字幕/音乐填 `—`，时间与时长空着），不编造导演的决定。
- 目标目录不得落在 `定稿/` 或 `剧本/` 内；写盘后用 `--校验 true` 逐份比对哈希，只有校验通过才算完成（与小说导出同一纪律）。

### 总纲（剧本圣经，对齐轮次）

总纲是全剧的创作宪法，结构取自《痴迷》参考案例（`docs/examples/痴迷-12集分镜剧本-参考案例.docx` 第一部分），固定七节，缺一不可（渲染器 `renderStoryBible`，校验 `validateStoryBible`）：

1. **类型/形式/文字目标/叙事线**：类型、形式、文字目标（每集分镜剧本字数目标）与叙事线（A线主角主线、B线暗线、C线辅线）。
2. **故事一句话**：一句话讲清全剧。
3. **开篇承诺与中心问题**：开篇讲了什么 + 悬念清单 + 主题 + 反题。
4. **世界硬约束与地理**：现实基底与唯一超自然规则 + 硬约束清单 + 核心地理空间清单。
5. **三段核心真相**：作者事实，不等于所有角色已知；固定三段。
6. **主要人物与人物弧（全剧统一规范）**：每位人物写清标准名、身份与人物弧；**曾误标过的名字必须记一条统一记录**，如「（原剧本曾误标为：伊恩[第2集]、Bear[第3集]，已全部统一为贝尔）」。本节同时是**人名注册表**的数据源：导出前检查全剧人名必须在册且只用标准名，未登记/误标直接阻断，不静默输出。
7. **分集结构与时间锚点**：按幕分组，每集一句话梗概 + 时间锚点（如「第1集（D1 周三白天至傍晚）：……」）。

### 短剧单集分镜形状（对齐轮次）

单集剧本（`剧本/短剧/集001.md`）按《痴迷》分镜形状写（渲染器 `renderEpisodeScript`，解析器 `parseEpisodeScript`，往返逐字节一致）：

- 场头：`集-场 日/夜／内/外 地点`，如 `1-1 日／内 苏家客厅`（旧版 `## 场01. 地点 时间 内/外` 已废弃，解析到会报迁移提示）。
- 人物行：`人物：名字（形象标识）、名字……`；场景环境行：`场景环境：……`（中文描写）。
- 镜头块：`△【镜头01｜时间：00:00—00:42｜景别：近景｜角度：平视正面｜运镜：固定镜头】`（五字段缺一不可；镜头号与时间码集内累计、集间重置），块内 △站位/动作/表情行各独立成行；无人物面部时用 `△【本镜头无人物面部，表情不适用】` 等变体行；`【环境声：……】` / `【字幕：……】` 各单独成行；集末一行 `【画面淡出黑场】`。
- 对白行：`角色（语速…，音量…，语调…，尾音…）：对白`，画外音在标注最前面加「画外音，」。
- **语言规则**：说明/场景/动作文字一律中文，对白按目标市场语言（海外题材为英文；总纲 `对白语言` 字段写明）。这是“输出永远中文”的边界：团队看的说明文字是中文，演员说的对白是目标市场语言。

### 集 / 场寻址键（平行于卷 / 章，不复用参数名）

小说用（卷，章）寻址；剧本用另一套键，工具参数名不得复用 `卷` / `章`：

- 短剧：`集`（集号，1–100，文件内显示为三位 `集001`）+ `场`（集内场号，1–4，显示为两位 `场01`）。
- 电影：`幕`（幕号，1–3，显示为 `幕1`）+ `场`（幕内场号，显示为两位 `场01`）。

编号辅助函数在 `packages/core/src/repo/paths.ts`：`episodeNo`（三位集号）、`sceneNo`（两位场号）。
