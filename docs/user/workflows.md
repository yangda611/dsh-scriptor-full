# 日常写作与恢复

Scriptor 8.4.4 配套 DSH 0.2.2-rc.1。操作见 [新编辑器教程](editor.md)。文件卡见 [结果卡与导出成品](result-cards.md)。参考资料见 [参考小说分析](reference-analysis.md)。图谱和流程状态见 [界面参考](ui-reference.md)。

新建对话并选择 **写作模式**，再打开原工作区继续。普通对话仍可手动编辑；AI 写作和编辑协作需要写作模式，旧对话不会自动切换。

旧项目先按 [升级指南](upgrade-backup.md#旧项目需要更新作品契约) 补充篇幅约定。

## 继续章节

1. 写明书名和范围。例如“继续这本书的第2章，先核对进度”。
2. 发送给工作台。
   成功时，工作台读取实际书仓，再决定要准备细纲、写稿、审读还是定稿。

换会话时，不需要手工重建一份当前章节状态表。

## 短剧与电影剧本：按集 / 按场推进

小说按卷、章推进；短剧按集推进，电影剧本按场推进，不要混用。

**短剧**（契约里 `输出形态` 是 `短剧` 的项目）：

1. 先定画幅：一次问完，给选项——1. 竖屏（★推荐，默认；手机上刷着看，9:16，每集 60–120 秒，一季 60–100 集） 2. 横屏（长视频平台点播，每集 10–20 分钟，一季 20–30 集） 3. 自己有想法，手动输入。拿不准默认竖屏，一句话就能改。
2. 分集大纲：每集只容一个想法，先说清钩子类型（第 1 集身份、第 2 集情感、第 3 集顿悟，此后轮换）、核心想法、爽点和结尾悬念，再动笔写剧本。
3. 一集一集写：写完一集就跑节拍检查（开场 3–5 秒进冲突、每 20–30 秒一个转折、结尾留钩子），不过就改，不凭感觉放行；再走审读。
4. 定稿落到 `剧本/短剧/集001.md` 起，每集一份。不要把剧本定稿放进 `定稿/`（那是小说的）。

**电影剧本**（契约里 `输出形态` 是 `电影剧本` 的项目）：

1. 故事稿：先把故事用散文写透（人物小传、情节主线、关键转折），再改编，不要直接跳去写剧本。
2. 分场大纲：按三幕分场，每场写清场景、人物、冲突、转折。
3. 剧本草稿：按专业格式写——场景标题、动作、角色、台词、括号提示；台词停顿只用 `(pause)`，不用 `(beat)`；音效写进动作行，音乐提示只进分镜头表。
4. 审读通过后，定稿落到 `剧本/电影/剧本.md`，全文一份。

两种形态都一样：契约里的 `市场`（海外 / 中文）只决定读哪套题材库，说明文字永远是中文；海外项目的演员对白才用英文。契约里还多了 `目标总字数`（建书前必定，和市场、输出形态一起写进契约，用来规划全书篇幅；每章的字数另在定调时商定，见下）。

## 起草时的字数反馈

写稿 Agent 用原生 `write/edit` 保存草稿后，会收到真实字数和契约篇幅的核对结果。它可以在自然情节节点先保存一次暂存稿，查看累计字数后继续；不强制按固定段落预算写作。

暂存稿名为 `稿N.起草中.txt`，不计入正式稿或待审稿。写完整章后仍须交付带元数据的 `稿N.md`。中断时暂存内容保留，恢复后可继续。

完整稿越界时，起草流程最多做一轮篇幅调整，并另存新稿。仍越界或字数未核验时，如实交接，审读继续独立复算。这个规则不会禁止作者之后提出新的修改要求。

第一份完整稿也以约定范围为目标，过短和过长都未满足要求。主控接稿时会独立读取交付文件核验字数，不只转述写稿代理的报告；后续改动后重新核验。

统计只对所列保存快照有效，不代表整章质量通过。没有已确认的篇幅约定时，不临时编造范围。Shell 保存不触发此回执；只返回局部文字的工具不能核验全文。

## 作者偏好与本书决定

跨作品的长期偏好保存在作者范围，单本书的决定保存在本书范围。可以明确说“只记在这本书”或“这是跨书偏好”。保存结果会显示实际归属。

相同内容不重复新增。要改变已有结论，先读取旧条目，再明确更新；旧文已变化时重新核对。临时讨论、流程日志和剧情复述不默认长期保存。旧记忆保留，不自动搬迁或删除。

## 修改设计或正文

保存文件、提交版本、工作台理解修改，这是三件不同的事。

1. 在书房编辑器里保存草稿、规划或世界书。
2. 让工作台核对影响。
   如果保存时报告版本冲突，先重新读取当前文件，避免覆盖更新。

在当前主会话打开书房并保存之后，检查保存结果：

- 文件已保存：磁盘已经更新。
- 版本已提交：已经留下 Git 记录。
- 已交给主控：通知已经送达。还要看主控随后的读取和核对结果。

如果只有标点或局部措辞变化，核对之后可以直接结束。如果改变了事实、人物目标或写作约束，说明受影响的内容和等你决定的事项。工作台不会因此自动重写下游，也不会推进下一章。

如果在外部编辑器或终端里改了文件，这次修改没有经过书房的保存通知。

1. 回到对应作品的对话。
2. 可以直接说：

> 我刚修改了《书名》的作品契约，把主角目标从复仇改为寻找真相。请读取当前文件，核对大纲、世界书和已定稿章节的影响，列出需要调整的地方，先不要改稿。

不需要专门的隐藏命令。“刷新书房”会同步目录和已打开的正文。有未保存的编辑时，它保留文字并提示比较。它不能代替上面这条核对请求。

主控忙碌或被中断之后，也可以说明文件和改动目的，请它从当前文件重新核对。不要为了唤醒它而反复保存相同内容。

修改未定稿内容时，可以返回相关流程。涉及已有定稿的设定变化，要核对影响，并走补偿或修订流程。不要直接改已确认的设计文件，也不要手写账本来绕过检查。

## 审核失败或模型中断

1. 先看失败来自哪里：正文问题、材料不足、配置或网络，还是你的意见。
2. 补足材料，或修好服务。
3. 继续对应的步骤。
   成功时，你能看到实际的审核记录或提交结果。

模型输出的一句“完成”，不能代替审核记录或提交结果。

## 暂停

1. 明确要求暂停当前章。
   成功时，当前章停止继续写入。
2. 下次开始时，先核对文件和 Git 状态。
   已完成的部分可以继续使用。取消或失败不是对后续写入的批准。

暂停期间，不要在别处手工改动同一章的文件。

## 卷末

1. 先核对计划章节、定稿和未回收事项。
2. 准备卷摘要候选。
3. 核对之后再确认。
   成功时，卷摘要与已核对的定稿一致。

窗口用尽，不等于整卷完成。无法确定时，应显示未知或待核对。开始下一卷之前，核实前卷沉淀和当前卷规划。

## 导出

1. 指定书、卷或章节范围，以及一个新的目标目录。
2. 先检查冲突，再写出定稿合集和来源清单。
3. 读取实际文件。校验通过后，交付成品卡。
   如果卡片不可用，明确给出路径。不要重复写盘。

导出不会把草稿混进定稿。平台上的排版和发布仍由你自己检查。工作台不会代你向小说平台投稿。

## 剧本导出

电影剧本与短剧单集走同一只读纪律，工具不同：只读 `剧本/` 里的定稿，不改书仓；草稿区里的剧本草稿不是真源，不导出。

1. 说清形态和集号：电影说“导出电影剧本”，短剧说“导出第 N 集”（短剧必须指明集号，电影不传集号）。
2. 先检查目标目录和冲突，再写盘。目标目录不能落在 `定稿/` 或 `剧本/` 里（会污染真源）；已有同名文件时拒绝新建、不覆盖，另选新目录。
3. 写盘后用同一参数加 `--校验 true` 跑一遍验收，只有校验通过才算完成。
4. 成品是两份：Fountain（`.fountain`，纯编剧层）和 Markdown（`.md`，编剧层 + 导演层分镜头表：镜号 / 场 / 景别 / 角度 / 运镜 / 时间 / 时长 / 画面内容 / 台词 / 对白标注 / 音响 / 字幕 / 音乐，共 13 列）。传了总纲还会多一份 `<书名>-总纲.md`，并先做人名一致性检查——全剧人名必须在总纲人名注册表里且只用标准名，未登记或用了曾误标的旧名会直接挡住，不静默输出。
5. 导出的剧本长什么样，先看 [短剧分镜剧本示例《夜市摊主》第 1 集](../examples/剧本导出示例/短剧-分镜剧本示例-夜市摊主集001.md)（总纲节选 + 第 1 集完整分镜）；最终输出格式的范例是 [《痴迷》12 集短剧全集分镜剧本](../examples/痴迷-12集分镜剧本-参考案例.docx)。分镜头表没填时，导出按场生成待填模板行（景别、角度、运镜等填 `—`），由导演补，工具不编造。
