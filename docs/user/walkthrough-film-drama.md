# 新手走查记录：从创建走到导出（短剧项目）

走查日期：2026-11-10（阶段 5）。走查项目：原创短剧《巷口面馆》（中文市场、竖屏短剧）。
走查依据：更新后的 `beginner.md`（§0.5、§5、§7）、`first-book.md`（§1、§6）、`workflows.md`
（短剧与电影剧本节、剧本导出节）。自动化复现：`packages/bundle/tests/phase5-walkthrough.spec.ts`
（3 个测试，见“自动化复现”一节）。

## 结论（先说）

**新手按文档能从创建走到导出，全程通过。** 建书时市场与输出形态的默认值按文档所说生效；
第 1 集按文档的短剧规则写完后渲染零警告、渲染—解析往返一致；导出按文档所说的三份文件
（Fountain + Markdown + 总纲）产出，人名检查通过，写盘后 `--校验 true` 通过。
走查中发现 1 处文档与实际不符（安装教程里的技能数），已改文档；未发现需要改代码的易用性问题。

## 走查步骤与实际结果

| 步 | 按文档怎么做 | 实际操作与结果 |
| --- | --- | --- |
| 1. 建书前定两样 | `beginner.md` §0.5：先定市场（海外 / 中文，默认中文）与输出形态（短剧 / 电影剧本 / 小说，默认小说），定完写进作品契约，之后不再悄悄改 | 调 `novel_create_book`，书名《巷口面馆》，构想七要素齐全，`市场: 中文`、`输出形态: 短剧`。返回 `ok:true`；读 `作品契约/契约.md`，frontmatter 里确有 `市场: 中文` 与 `输出形态: 短剧`。通过 |
| 2. 建书时被问到两件事 | `beginner.md` §5：建书前工作台先问“面向海外还是中文市场？”和“要出短剧、电影剧本还是小说？”，不说就按默认来 | 两句问话见 `novel-inspiration` SKILL.md 第 3 步（建书前先定市场与输出形态），措辞与文档一致，大白话，无术语；`novel_create_book` 的参数说明里两项都写明“不填默认中文 / 不填默认小说”。通过（对话层按技能文本核对，见“局限”） |
| 3. 定画幅 | `workflows.md`：短剧先定画幅，竖屏还是横屏，拿不准默认竖屏 | 选竖屏（9:16，每集 60–120 秒，一季 60–100 集）。通过 |
| 4. 写第 1 集 | `workflows.md` + `first-book.md` §6：一集只讲一个想法（本集：所有人都以为面馆要关了，其实有人等了三年）；台词中文一句不超过 12 个字；第 1 集身份钩；结尾留悬念、切在问题上 | 写《巷口面馆》第 1 集《等了三年的面》：3 场、31 句台词、共 187 字（竖屏要求 180–360 字），最长一句 9 字；钩子类型身份；结尾悬念“妈妈当年为什么离开面馆？”（问题，不是答案）。渲染零警告；渲染—解析往返逐字节一致。通过 |
| 5. 定稿位置 | `workflows.md`：短剧定稿落 `剧本/短剧/集001.md`，不要放进 `定稿/` | 第 1 集正文写入 `剧本/短剧/集001.md`，`定稿/` 未动。通过 |
| 6. 导出 | `beginner.md` §7 第 4 步：说清形态和集号；目标目录不能落在 `定稿/` 或 `剧本/` 里；写盘后用 `--校验 true` 验收 | 跑剧本导出 CLI：`--形态 短剧 --集 1 --总纲 总纲.json`，退出 0；产出 3 份文件：`巷口面馆-短剧集001.fountain`、`巷口面馆-短剧集001.md`、`巷口面馆-总纲.md`；人名检查 `{ ok: true, problems: [] }`。写盘到书仓外目标目录后 `--校验 true` 退出 0，校验通过。通过 |
| 7. 总纲与人名检查 | `workflows.md` 剧本导出节：传了总纲多一份总纲文件，并做人名检查；未登记或用了曾误标旧名会直接挡住 | 总纲按《痴迷》七节写（类型 / 形式 / 文字目标 / 叙事线、故事一句话、开篇承诺与中心问题、世界硬约束与地理、三段核心真相、主要人物与人物弧、分集结构与时间锚点）；人物含曾误标统一记录“老板娘[第1集]，已全部统一为林晚”，总纲文件里确有该行；人名检查通过。通过 |
| 8. 对照导出范例 | `beginner.md` §7：导出的剧本长这样，先看《夜市摊主》示例与《痴迷》参考案例 | 《夜市摊主》示例（总纲节选 + 第 1 集完整分镜）与《痴迷》参考案例（`docs/examples/痴迷-12集分镜剧本-参考案例.docx`）均在仓内，链接可点；本次导出的三份文件与示例同一形状（编剧层 + 导演层分镜头表 13 列）。通过 |

## 局限（诚实说明）

- 对话层的提问与确认（第 2 步）是按技能文本人工核对的，未在真实 DSH 桌面端里点一遍；
  建书、渲染、导出走的是真实代码路径（`createBook`、`renderEpisodeScript`、
  `screenplayExportCli`），不是模型口头承诺。
- 走查只覆盖短剧竖屏第 1 集 + 导出；电影剧本管线（故事稿 → 分场大纲 → 剧本草稿 → 审读）
  与横屏短剧已有阶段 2/3 的端到端测试覆盖，本次未重复走查。
- 未发现需要改代码的易用性问题，因此本次无代码改动（除走查测试本身）。
